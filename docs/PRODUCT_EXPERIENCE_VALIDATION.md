# 阅读优先的产品体验优化

2026-10-10，本地分支 `codex/pdf-review`。这一轮把商业产品体感落实为可检查的视觉、操作与稳定性要求。保留产品名称、HTML / DOCX / PDF、离线单文件和既有批注协议；没有推送、创建 PR、部署或修改 GitHub 发布资产。

## 最终体验与验收依据

| 要求 | 实现与当前证据 |
| --- | --- |
| 简洁且有艺术气息 | 保留暖白纸张、墨绿、铜色、局部渐变与文档插画；首页使用本机衬线标题，工作区用清楚的无衬线文字。提高说明和批注操作字号，统一设置、交接、返回对话框的排版。检查桌面与窄屏截图，并由独立 agent 两次只读审查。 |
| 正文占据主要空间 | 常态只留一行流程提示，详情浮在正文上方。代表性 1440×1000px 工作区中，预览外框高760px，阅读区域高904px，约84%。展开详情、保存、关闭提示均验证外框坐标与尺寸不变；不缩放原文内容来制造空间。 |
| 新建、编辑、查看不混淆 | 编辑器显示“编辑批注 · 02”，对应卡片显示“正在编辑”与暖色标记；当前查看记录使用绿色标记。新建时为“清空草稿”，编辑已有记录时为“取消编辑”。文字范围显示字符数量，局部摘要可展开；取消选择保留意见。 |
| 反馈清楚且不挤动文档 | 普通打开、选中、保存提示浮在阅读区底部并自动退场；悬停或聚焦可暂停退场。错误不自动消失，可关闭。实际损坏 JSON 导入测试验证错误持续、工作区保留，以及后续成功提示的停留和退出。 |
| 桌面连续审阅顺手 | 保留侧栏拖动、左右布局、收起与恢复、按筛选逐条查看、长意见展开、定位复核和完成记录。默认352px侧栏在窄桌面临时使用300px，其他自选尺寸继续受可用空间约束。实际导出副本和本机恢复验证偏好、草稿、选区不会丢失。 |
| 手机阅读与批注能自然往返 | 底部“阅读 / 写批注 / 批注”入口分别展开编辑器和记录面板；两者记忆各自滚动位置。点击文字、元素/区域、单页模式时先回到正文，选择目标后展开编辑器，不抢输入焦点；关闭或Esc保留草稿和选区。手机隐藏左右布局选项，文件夹文档选择入口仍可用。 |
| 小屏保存可达 | 输入字号16px，保存区在面板内保持可见；320 / 390 / 600 / 760px验证无应用水平溢出、面板边界和保存按钮完整可见。可视视口变化时调整面板高度和底部位置，输入时隐藏底栏；400px可视高度的模拟测试验证输入、滚动到保存操作及恢复。 |
| 动画连续、轻巧 | 菜单220ms、弹窗280ms、手机面板展开230ms/收起150ms，卡片以190ms透明度和小幅位移进入，不使用高度入场推移列表。检查菜单、弹窗和面板中间状态及快速反转；支持系统减少动态效果，关闭中的区域不可聚焦。 |
| 交接与恢复保持可靠 | HTML、DOCX、PDF均完成实际上传、批注、轻量/完整导出、原文件配对、任务复制、ZIP交接、处理记录、重载与离线继续编辑。文件夹关联重载、资源变化、撤销重做、草稿和失败保留有既有工程回归覆盖。 |
| 网站与离线入口一致 | 本地构建网站，补查导航条占用的高度，手机正文不被底栏遮住。七组网站检查通过：精确下载内容、在线体验、恢复、离线副本移除网站导航，以及减少动画。未修改线上部署。 |

## 保存面板遮挡修复

同日根据用户截图复现：打开保存面板后，审阅进度条盖住其中一段说明。顶部栏与进度条原本都处于20层，保存面板自身的80层无法越过父级；在重叠点的实际命中检测中，最上层是进度条的“agent已返回文件”按钮。修复为只在保存菜单打开及退出动画期间提升整个顶部栏，使其高于工作区浮层和手机批注面板，同时保持格式菜单与模态窗口的层级。

Chrome / Edge UI回归均通过：1440、1280、900、760、600、390、320px，打开保存面板后逐点检测内部区域的实际最上层元素，手机同时保持批注面板展开；继续验证格式菜单位于保存面板之上。截图位于 `output/playwright/design/backup-layering-*.png`，两款浏览器日志为 `layering-chrome.log` 与 `layering-edge.log`。Chrome动效、焦点、临时状态清理及完整副本重开回归通过。此修复后的单文件入口为7,026,001字节。

这次补充了此前仅检查菜单可见性、开合及屏幕边界时遗漏的遮挡检测。未推送或部署；本次浏览器已全部关闭，没有启动临时服务器。`PROCESS_CLEANUP_COMPLETE`。

## 2026-10-11 补充界面与操作排查

本轮复现并修复以下问题：

- 手机键盘可视高度模拟为400px时，点击保存会先触发输入框失焦。旧逻辑立即取消键盘布局，保存按钮从原位置移开，一次真实tap后批注仍为0条。现按可视视口判断键盘占用，失焦不再提前移动面板；一次tap保存成功，保存按钮位置保持不变。双指缩放不再被误认为键盘。
- 底部操作栏是工作区的兄弟节点，无法继承工作区上的视口底部偏移。现同步设置其偏移，检查780px可视高度及24px顶部偏移时仍完全位于可视范围。完整副本会清除两个节点的临时偏移。
- 设置弹窗的420px固定最小高度，在1280×320窗口将关闭按钮放到了屏幕上方（-38至-4px）。现约束为可用高度并让内容区滚动。1280×320、800×400、600×320、390×400均验证关闭按钮可点，使用说明、快捷键和工作区内容末尾可滚动到达。
- 手机从批注记录进入位置对照，再点击“在文档中查看”或“查看当前文档”时，记录面板仍挡住正文与“返回对照”。现进入文档查看时收起面板；实际重载修改后的HTML，检查查看、返回、确认位置及已完成记录复核，批注意见、revision和原定位历史保持正确。扫描页“框选区域”入口同步沿用选择模式的返回正文行为。
- 手机短窗口仍使用280px工作区及350px iframe最小高度，600×400时工作区延伸到底部403px、iframe延伸到604px，而底栏从334px开始覆盖。现预览随可用高度缩小。600×400、760×480、390×600验证工作区在底栏上方，iframe不超过预览容器，文档最后一部分可以在自身视口内滚动到达。

新增 `npm run test:frontend-robustness`，Chrome 154.0.8037.98和Edge 155.0.4283.45四组回归通过，日志及截图在 `output/playwright/robustness/`。另通过93项核心测试、构建一致性、既有UI、产品体验和动效回归；Chrome交接与HTML/DOCX/PDF位置复核、离线重开以及七组网站检查通过。本地网站下载与当前入口一致。

手机键盘、双指缩放与触摸为工程模拟，未进行实体手机或Windows真机验证。本次独立子agent只读复核并确认了短窗口设置问题，修复由主agent完成。入口7,026,664字节，未增加依赖或修改批注协议；仅本地构建、提交，没有推送、PR、线上部署或发布资产变更，`videos/`保持原状。
