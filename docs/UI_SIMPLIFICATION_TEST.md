# 首次使用与任务交接简化验收

日期：2026-10-08。分支：`codex/docx-review`。仅本地开发，不推送、部署或更新发布资产。

## 独立用户测试

两轮测试代理均使用 gpt-6.1-sol，分别以新用户身份操作。代理只获知工具入口、虚构测试文档位置及用户目标，只能读取可见界面、使用 Computer Use 操作；未提供源码、内部状态、产品操作教程或上一轮反馈。复制任务后检查剪贴板内容用于确认交接结果，没有向外部服务发送文档。

第一轮发现 Word 支持不明显、空工作区有过多尚不可用的控件、原生选择器等待不明确且不能取消、示例批注提前完成引导步骤、回传流程难以发现。代理在系统选择器阻塞后完成 HTML 示例批注，没有成功导入 Word，不能将这一轮计为 Word 通过。

修改后的新代理从界面判断出支持 HTML / Word，通过可见兼容选择入口导入《澄川试点复盘.docx》，查找“预算”、跳转匹配内容、保存元素意见，并找到“交给 agent”及复制任务。代理能区分“导入处理结果”与“读取修改后的文档”。本轮盲测没有实际接收另一 agent 的修改文件，完整结果回传由浏览器回归覆盖；上一轮真实三轮 agent 修改记录见 [DOCX 用户测试](DOCX_USER_TEST.md)。

两轮原始报告与截图存放在本机 `output/docx-user-test/`：`ui-simplification-baseline.md`、`ui-simplification-after.md` 和 `qa/`，不随提交公开。

## 已实现的简化

- 空工作区突出“打开文档”，次要入口为“先体验示例”；尚未使用的编辑、批注与导出控件暂不显示。恢复保存失败时仍显示重试入口。
- Word 导入后提供“目录与查找”，在长文档里按标题或关键词跳转；跳转不创建批注，不改变选区或草稿。
- 原生选择窗口等待期间显示“取消选择”和“使用兼容选择”；取消后保留工作区，迟到的旧窗口结果不会覆盖新选择。
- 保存意见后引导“交给 agent”。交接面板只突出“附上原文档、复制修改任务”；全文默认折叠，剪贴板失败时自动展开供手动复制。
- 待完成总数优先显示，再区分新增、更新和已回报仍待处理。已完成记录作为历史保留。
- 面板内提供回传后的两步操作，导入结果后也提供读取新文档的直接入口。完整副本不重复保存任务全文、目录、搜索结果与派生预览。
- 新窗口初始化后才出现的保存记录会补充恢复提示；已打开文档的窗口不会被其他窗口的保存通知替换。

## 验证与复现

`npm run test:simplification` 覆盖空界面、真实文件选择入口、等待选择的取消与迟到结果、Word 目录和重复原文查找、四种任务状态、剪贴板失败、轻量导出、结果导入后的下一步、完整副本离线恢复及跨标签迟到保存提示。使用 `BROWSER_PATH` 指定 macOS Chrome 或 Edge，可重复运行同一套件。

62 项 Node/Python 单元与协议测试通过。HTML 端到端、结果生命周期、桥接、原文件重载、存储恢复、易用性、UI 与动画回归通过。Chrome / Edge 的 DOCX 主流程与简化专项通过。Word 源文件字节不被界面操作改写，轻量 JSON 不携带原文件快照。

## 尚存边界

新用户仍认为“元素”略抽象；本轮补充了“点击段落、表格或图片”的提示，模式名称仍保留。回传详细步骤折叠以优先呈现首次交接，入口在普通桌面高度可见，较小窗口可滚动。产品名称按现有约定保留 HTML 批注，首页明确列出 Word 支持。

原生关联自动测试发现：关闭刚恢复 OPFS 文件句柄的标签后立即刷新另一标签，Chrome 曾整体退出。浏览器 stderr 报 `Detected dangling raw_ptr in unretained`，日志存于本机 `output/docx-user-test/docx-session-browser-debug.log`。测试保留恢复标签到收尾，再验收原标签真实刷新；此调整没有修复或证明消除浏览器原生崩溃。OPFS 的自动测试也不能替代用户手选磁盘目录的权限实测。

Chrome / Edge 的 DOCX 原生关联套件在调整后均通过，包括目录结果回传、原标签刷新、草稿与关联恢复、轻量配对及 gzip 离线继续编辑。

浏览器实测平台为 macOS，Chrome 154.0.8037.98、Edge 154.0.4258.62。没有 Windows 真机测试，Windows 路径与编码契约测试不能视为 Windows 实测。
