# 新版本重载与重新定位验收

日期：2026-10-08。分支：`codex/docx-review`。仅本地开发，不推送或部署。

## 使用流程

agent 交回处理结果后，导入结果并读取修改后的原文档。重载提示会显示已完成、待处理与需要确认位置的数量；文件夹关联下同时读到结果时，还会显示本次新完成的意见。撤销结果后，计数按当前状态更新。

工具分批核对待处理目标，不自动标记任何意见完成，也不移动预览或覆盖草稿。已完成意见继续作为历史记录，不检查已完成的旧目标。

- 位置与原文匹配：可以继续审阅。
- 通过原文找到候选：原位置有变化，请核对。
- 多处候选：无法确定对应哪一处，不自动绑定。
- 无法确认：原文、元素或属性可能已修改或删除。这个提示不是“agent 已完成”的判断。

点击“查看需确认的批注”，可筛选后三种情况。点击“重新选择位置”，原意见会留在编辑框，旧批注在点击“更新批注”之前不被修改。保存后沿用批注 ID、增加 revision，并保留原定位；取消、撤销与重做均受现有草稿保护。

## 数据与交接

可选 `annotations[].targetHistory` 记录之前的 revision、target、view（如存在）和重定位时间，最多 100 次。当前 `target` 才是本轮修改依据；旧定位只作记录。HTML schema 1、DOCX schema 2 与结果协议版本保持不变，旧批注不要求该字段。

历史按各自目标类型校验。DOCX 历史保留当时的源文件哈希，不在新版原文档中强行解析旧路径。轻量 JSON 保留必要定位历史，不包含源文件快照；完整副本仍只保留一份当前源文件。Python 检查仅简要列历史版本与类型，不输出历史全文或 Base64。

重新定位后，旧 revision 的 agent 回报不能关闭新版意见。自动检查与手动定位都核对通道、请求和当前批注版本，迟到结果不能覆盖已经保存的新位置。

## 验证

两位 gpt-6.1-sol 子代理分别完成协议实现/独立审查与真实浏览器回归。独立审查发现手动定位迟到回包缺少版本保护，已补充请求 token、revision 和目标快照校验，并加入针对该复现的回归。

`npm test` 的 67 项测试通过，新增历史协议测试覆盖缺省旧数据、跨目标类型、顺序与版本边界、100/101 次上限、无效目标/视口/时间、完整与轻量导出、结果应用和 Python 检查。

`npm run test:reload-review` 在 macOS Chrome / Edge 验证 HTML 与 DOCX：

- 14 条意见中的 13 条待处理分 10+3 两批检查，已完成目标跳过。
- 删除、重复原文、移动目标、整体意见分别验证无法确认、歧义、候选与匹配状态。
- 每一批检查都保持 iframe 滚动、选区与未保存草稿。
- 重新定位取消、同 ID 更新、旧目标历史、撤销/重做、旧 revision 回报拒绝。
- 损坏 DOCX 重载保留旧报告、定位与草稿。
- 丢包后显示未检查，重试可完成；旧通道和旧手动定位结果不会覆盖新状态。
- 轻量/完整导出、Python 检查、离线重开继续编辑，以及当前/历史 DOCX 源哈希。

主流程回归包括 HTML 端到端、桥接、重载、结果生命周期、DOCX 内容预览、轻量配对、易用性和原生关联恢复。没有 Windows 真机验证。
