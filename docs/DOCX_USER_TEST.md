# DOCX 真实用户模拟验收

日期：2026-10-08；本地分支：`codex/docx-review`。本轮未 push、创建 PR 或部署网站。真实操作使用 Computer Use；文档制作、独立定位复核、agent 交接与回归验证由 gpt-6.1-sol 子 agent 协作。

## 文档与方法

生成六页虚构业务报告《澄川客户服务平台试点复盘与上线方案》，包含中英混排、emoji、标题层级、跨样式文字、重复段落、多级列表、8 张表（含嵌套表及横向/纵向合并）、2 张带替代文字的图、图注、脚注、外链、内部书签、页眉页脚、显式分页、原生 Word 批注及插入/删除修订。此报告有脚注，没有尾注；尾注仍由既有浏览器定位套件覆盖。

本机 Microsoft Word 16.113.1 实际打开原文档及第三轮最终文档，均显示六页，没有报错。使用 bundled LibreOffice 渲染后逐页检查六张 PNG。子 agent 同样逐页检查了每轮编辑后的文档。

原文件 SHA-256：`26db7b1a0585d7f980ae337fee12e094659dd0b600274588b7ca7abef7b151d9`。测试结束再次核对一致。工具未修改原件；agent 修改发生在各轮独立工作副本。

最终 DOCX SHA-256：`5b257110e9d2c1c3b794c793b1683cdb38f11c300683a668277c59cda57a8ce2`。实际最终导出为 21,881 字节轻量 JSON 与 859,502 字节完整工作区 HTML；独立检查确认两者批注记录相同（排除轻量导出的派生 taskState），轻量 JSON 不包含文件快照、图片、预览或全篇索引。

交接 agent 首轮只收到实际复制任务、实际导出 JSON、原 DOCX 工作副本及允许的公开协议助手，不得读取产品实现、测试或生成器。第三轮进一步只依据文档和自包含复制任务完成工作，没有调用项目辅助脚本。定位复核由另一个 agent 直接解析原始 ZIP/XML，独立于产品实现。

## 真实界面流程

通过本地单页预览服务和真实文件选择事件导入文档。没有向页面注入批注或模拟导出数据。

1. 选中响应时间中的跨样式文字，取消选择后草稿仍在，重新选择并保存。实际用双击与 Shift+End 扩展选区，精确原文为“18 分钟，目标为 12 分钟。”，对应源段落 UTF-16 `[12,28)`。
2. 选择“客户沟通记录”下的第二个重复段落、企业版可用性单元格、响应时间图、嵌套表标题，并保存元素意见；使用“选父级容器”选到单元格。
3. 保存整体意见；撤销至 5 条、重做到 6 条。切换右侧批注栏，刷新恢复 6 条批注和未保存草稿。
4. 复制真实任务、下载轻量 JSON 与完整 HTML 副本。独立原文解析证明六个定位分别指向预期源段落、表格单元格、图片关系/媒体哈希及整体范围。
5. agent 完成六条修改，返回修改后的 DOCX 和结果。界面导入后显示 0 待处理 / 6 已完成；重载真实修改文件显示新正文，记录保留。
6. 编辑已完成响应意见，变为 revision 2 / 已更新；新增删除建议段意见。再次导入旧批次，仍为 2 待处理 / 5 已完成，没有关闭新版本意见。
7. 第二轮 agent 只处理这两条：补充负责人完成；删除目标承载原生 Word 批注，保持 open，要求明确随段删除还是迁移锚点。界面显示 1 待处理 / 6 已完成及处理反馈；兼容重载显示新负责人句子。
8. 模拟用户编辑删除意见，明确同时删除目标段及其原生批注 id=0。第三轮 agent 完成后，实际导入结果、重载文档，确认目标段不存在、前三条整改事项保留，界面为 0 待处理 / 7 已完成。该条的原文和两次处理历史仍可查看。
9. 在独立工作区打开首轮轻量 JSON，错误版本被拒绝且配对状态保留；选择匹配原文档恢复六条意见。实际点击内部书签、脚注及返回链接；修复后脚注往返保持同一预览正文。
10. 实际重新导入下载的完整 HTML 副本，恢复六条意见，继续保存第七条再撤销。最终三轮工作区再次通过真实下载交付完整副本、轻量 JSON 和复制任务。

第一轮只修改 `word/document.xml`；第二轮只追加负责人；第三轮仅改变 `word/document.xml` 与 `word/comments.xml`，删除被明确授权的段落和批注实体/锚点/引用。逐轮逆向还原已授权修改后，相关 XML 与该轮源文件规范化结果相同；其余 ZIP 部件字节一致，证明完成意见未被重复执行、其他元素未被顺带删除。

## 发现与修复

| 问题 | 影响与修复 |
| --- | --- |
| 脚注编号跳转绕过内部链接保护 | 编号因排除文字偏移而被标为工具辅助内容，早返回漏掉 preventDefault。现在内部脚注链接留在预览中滚动，辅助编号仍不污染文字定位。 |
| 系统选择器拒绝后缺乏替代入口 | 状态提供兼容选择按钮；设置使用说明提供直接兼容打开/目录/重载；配对提示提供兼容选择。失败与取消保留原工作区。 |
| DOCX 目录恢复只保留 HTML 候选 | 刷新后其它 DOCX/XHTML 候选消失。恢复过滤改为保留全部支持的文档扩展名。 |
| 空工作区恢复还询问放弃记录 | 点击继续上次审阅时无当前内容，却询问替换恢复记录。空工作区直接恢复；已有编辑仍受保护。 |
| DOCX 交接提示仍要求 HTML | 复制成功、剪贴板失败弹窗及轻量导出提示明确要求原 DOCX。任务自带结果协议，助手脚本可选；明确同时返还修改后的 DOCX 和结果 JSON。 |
| 待处理原因藏在历史中 | 当前版本 open 回报直接显示处理反馈摘要，完整说明仍在历史；编辑后旧反馈隐藏为历史。导入结果提醒重载文档查看正文。 |
| Word 标题、常用图注产生多余转换警告 | Title 映射为标题，Subtitle/Caption 保留段落；本例三条无意义样式警告消失，实际预览边界提示保留。 |
| 保存状态暗示未发生的下载 | 初始/无改动状态使用中性说明；真实导出仍由下载提示确认。 |
| 窄屏文件夹按钮缺少可访问名称 | 为仅剩图标的按钮补充明确标签。 |
| 静态检查助手 --help 返回失败码 | 常规帮助返回 0，错误参数仍失败。 |

删除原生 Word 批注的冲突是文档任务需要澄清的实际意图差异，不是自动定位失败。该场景没有通过猜测或误标完成掩盖问题。

## 本地交付与边界

产物集中在 `output/docx-user-test/`（忽略目录，不提交生成文档或录制资产）：原始 DOCX、三轮工作副本及结果、实际导出的最终工作区 JSON/HTML、复制任务、逐页渲染、独立定位证据及真实界面截图。生成器 `generate.py` 保留在同目录；它使用本机 bundled 文档环境和字体路径，不宣称开箱跨平台复现。

Computer Use 的鼠标拖选受到嵌套 iframe 坐标检查限制，因此本轮采用实际双击和键盘扩展选区，不能宣称物理鼠标跨单元格拖选已实测。跨段/跨单元格定位由既有程序回归覆盖。

Chrome 扩展未开放文件 URL 上传权限，本轮没有修改该权限；主要真实导入使用内置浏览器的兼容文件选择。系统 File System Access 选择器在自动控制环境有取消或等待现象；磁盘持久权限不是此次 Computer Use 验收通过项。自动恢复套件使用真实 OPFS handle，但不能替代手选磁盘权限验证。

本机为 macOS；未进行 Windows 真机验证。完整副本的离线 `file://` 运行由自动回归验证；本轮 Computer Use 验证的是将实际下载副本重新导入后继续编辑，没有绕过浏览器文件 URL 安全限制。

后续易用性建议：文档目录与搜索入口；首次 DOCX 打开时提供更短的格式专用说明；交接任务开头显示新增/更新/已完成数量；让原生 Word 批注的未预览提示更容易发现。它们是后续建议，不宣称已实现。
